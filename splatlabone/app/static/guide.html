What SplatLab is

SplatLab One is a 3D Gaussian Splatting (3DGS) pipeline for Olares One. You import photos or video, run a configurable reconstruction pipeline, and get viewable / editable splat assets.

It combines:

  • Structure-from-Motion (SfM) — estimate camera poses from photos
  • Feed-forward geometry — neural networks that predict poses + depth when COLMAP is slow or fails
  • gsplat training — optimize 3D Gaussians for high-quality novel-view synthesis
  • Web UI + REST + MCP — human workflow and agent automation on the same API

The app runs as a GPU workload on Olares One (RTX 5090M). Non-admin users reach it through an nginx client chart; the GPU server is a shared admin subchart.

End-to-end workflow

Import (UI / REST / MCP)
  └─► uploads/ds_xxx/images/  [+ sparse/0 if COLMAP zip]

Create job (preset + overrides + realtime mode)
  └─► Job queued → PipelineRunner

Workspace setup
  └─► workspaces/job_xxx/images  ← symlink or copy from dataset
  └─► workspaces/job_xxx/sparse/0  ← copy if dataset already has COLMAP

Stage 1: SfM (optional)
  └─► glomap or colmap → sparse/0 (poses + sparse points)
  └─► publish sfm_sparse_ply

Stage 2: Geometry (optional)
  └─► vggt_omega | da3 | lingbot_map | instant_splat
  └─► writes sparse/0 + backend-specific artifacts (infer_gs.ply, etc.)
  └─► publish geometry artifacts

Stage 3: gsplat train (skipped if geometry_preview mode)
  └─► simple_trainer.py --data-type colmap --data_dir workspace
  └─► outputs/job_xxx/splat/  (ckpt, ply, splat)
  └─► export ply_compressed for SuperSplat editing

View / download
  └─► Viewer: sparse points | infer_gs SuperSplat | gsplat Viser
  └─► REST: /api/v1/scenes/{job}/…

Jobs emit SSE events on /api/v1/jobs/{id}/events so the UI and MCP can show live progress without polling.

Why COLMAP is the hub

Every geometry backend and SfM stage converges on the same on-disk layout:

  • workspace/images/ — input photos (filenames referenced by COLMAP)
  • workspace/sparse/0/ — COLMAP model: cameras.*, images.*, points3D.*

gsplat only knows one dataset format here: --data-type colmap. Feed-forward networks (VGGT-Omega, DA3, LingBot) don't train Gaussians themselves — they produce COLMAP poses (and sometimes sparse points) so gsplat can refine a splat scene on Olares One hardware.

DA3 is special: it also exports infer_gs.ply (feed-forward 3D Gaussians) for instant preview in SuperSplat, while its COLMAP export feeds the gsplat refine step.

Helpers live in pipeline/colmap_io.py: write/read COLMAP text models, export sparse PLY for visualization, unproject depth to 3D points.

Pipeline stages

1. SfM — Structure from Motion

pipeline/sfm/ — classic photogrammetry from unordered photos.

BackendWhat it runsWhen
glomapglomap mapper if binary present; else COLMAP 4 global_mapper (feature_extractor → exhaustive_matcher → global_mapper)quality preset
colmapClassic COLMAP mapper (not global_mapper)Advanced override
skipNo SfM — use ingested COLMAP or geometry front-endFeed-forward presets

COLMAP (binary in Docker image from colmap/colmap:latest) finds feature matches across photos and solves for camera intrinsics/extrinsics plus a sparse 3D point cloud.

2. Geometry — feed-forward pose providers

pipeline/geometry/ — neural alternatives when you skip SfM or need faster / more robust init.

BackendLibraryOutput
vggt_omegaMeta VGGT-OmegaPoses + depth → COLMAP sparse/0 + sparse PLY preview
da3Depth Anything 3COLMAP export + infer_gs.ply (feed-forward Gaussians) + optional GLB
lingbot_mapLingBot-Map GCTStreamStreaming video geometry → COLMAP + sparse PLY
instant_splatInstantSplat + MASt3R3–12 images → COLMAP via init_geo.py
none—SfM or pre-ingested COLMAP only

3. gsplat train — Gaussian optimization

pipeline/train/ invokes /opt/gsplat/examples/simple_trainer.py:

  • default subcommand — standard 3DGS with adaptive densification
  • mcmc subcommand — 2DGS surfels + MCMC densification (noisy init friendly)
  • --with_eval3d when representation=2dgs
  • --pose_opt when pose_opt=joint (refine poses during train)
  • --port for live Viser during progressive_splat mode

4. Export

pipeline/export.py uses gsplat.export_splats() from latest checkpoint:

  • scene.splat — compact splat format
  • point_cloud.ply — standard PLY
  • scene.ply_compressed — SuperSplat edit format
  • *.pt checkpoint — for gsplat Viser viewer

Docker & models

Runtime image: ghcr.io/coynntis/splatlabone:1.1.0

  1. Multi-stage Dockerfile: PyTorch cu128 builder compiles gsplat + pip deps; COLMAP copied from official image; geometry repos via fetch_backends.py
  2. Build on Olares via dockerbuilderone MCP — zip splatlabone/docker/ with synced app/
  3. Helm initContainer prefetches model weights into persistent cache volumes
  4. Python/static hotfixes can ship via ConfigMap overlay without full image rebuild

Details: splatlabone/docker/README.md

Olares One constraints

  • RTX 5090M — 24 GB VRAM; chunk VGGT/DA3 on long sequences
  • PyTorch cu128 + gsplat — sm_120 Blackwell support
  • 96 GB DDR5 — COLMAP matching benefits from 16 CPU threads
  • Core Ultra 9 275HX — AVX2, no AVX-512/AMX (KTransformers-style CPU paths not used here)
  • Set GITHUB_TOKEN for ghcr.io image pull; HF_TOKEN for gated weights
